# ADR 0006: MCP protocol upgrade

- Status: proposed
- Date: 2026-09-05
- Track: future_capabilities_20260905 / T6
- Deciders: maintainers

## Context

The current stdio JSON-RPC server exposes tools under an older protocol revision. A newer revision can add resources, tool annotations, output schemas, structured content, and negotiation using the standard library. Compatibility behavior must be explicit.

## Decision

Go — plan a new track `mcp_resources_implementation`. Delivery shape: standard Web API or Python stdlib only; no vendored dependency is introduced by this research track.

## Consequences

The proposal improves interoperability or operator capability while keeping runtime and bundle size unchanged until a separate implementation track is approved. It adds documentation and future maintenance work; security review, fixtures, browser support, and reproducible verification remain mandatory. No product claim changes before implementation.

## Go/no-go checklist

- [ ] Zero-install feasibility confirmed: standard Web API / Python stdlib; no vendored file required *(mandatory)
- [ ] Prerequisite sibling tasks listed with track_id/T<n>: mcp_resources_implementation *(mandatory)
- [ ] Verification method named (conformance tool, fixture, or test) that will prove the capability works: focused fixture and acceptance test *(mandatory)
- [ ] Older clients are supported by downgrade to the highest mutually supported version
- [ ] Resource URIs and MIME types for profiles and CDX are `file://` and application JSON/text
- [ ] Every tool has drafted annotations and an output schema
- [ ] Depends on `cli_parity_20260905` shared test fixture for a smoke test
